# backend

Minimal [ElysiaJS](https://elysiajs.com/) + [Bun](https://bun.sh/) API with async task processing, a text fact-checking pipeline, WebSocket updates, Swagger UI, and an optional Redis cache.

## Requirements

- Bun 1.4+

## Setup

```bash
bun install
cp .env.example .env
bun run dev
```

Bun loads `.env` automatically. The server listens on `http://localhost:3000` by default.

### Environment

| Variable | Default | Description |
| --- | --- | --- |
| `PORT` | `3000` | HTTP port. |
| `REDIS_URL` | empty | Optional Redis/Valkey URL for cache and task snapshots. Empty means memory. |
| `DEEPSEEK_API_KEY` | empty | Enables DeepSeek chat completions and optional ASR. |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | DeepSeek API base URL. |
| `DEEPSEEK_MODEL` | `deepseek-flash` | DeepSeek model used for gate/summary. |
| `DEEPSEEK_INPUT_USD_PER_1M_TOKENS` | `0.30` | Input rate for cost tracking. |
| `DEEPSEEK_OUTPUT_USD_PER_1M_TOKENS` | `1.20` | Output rate for cost tracking. |
| `DEEPSEEK_ASR_USD_PER_HOUR` | `0.116` | DeepSeek transcript rate. |
| `OPENROUTER_API_KEY` | empty | Enables OpenRouter embeddings and optional transcription. |
| `EMBEDDING_MODEL` | `openai/text-embedding-3-small` | OpenRouter embedding model. |
| `TRANSCRIPT_PROVIDER` | `auto` | `auto`, `openrouter`, or `deepseek`. |
| `TRANSCRIPT_MODEL` | `openai/whisper-large-v3` | OpenRouter transcription model. |
| `TYPESAFE_API_KEY` | empty | Enables the TypeSafe Jev claim gate. |
| `JEV_MODEL` | `jev-latest` | Jev model. |
| `JEV_CHECKABLE_THRESHOLD` | `0.6` | Probability needed to treat a claim as checkable. |
| `RAG_TOP_K` | `5` | Candidates considered per lookup. |
| `RAG_MIN_SCORE` | `0.82` | Similarity needed for a cache hit. |
| `RAG_TTL_SECONDS` | `604800` | Fact-check cache TTL (7 days). |
| `REQUEST_BUDGET_USD` | `0.05` | Per-task spend cap. |
| `AI_TIMEOUT_MS` | `20000` | Timeout per provider request. |

Example:

```dotenv
PORT=3000
REDIS_URL=redis://localhost:6379
DEEPSEEK_API_KEY=sk-...
OPENROUTER_API_KEY=sk-or-...
TYPESAFE_API_KEY=...
```

If `REDIS_URL` is set but Redis cannot be reached at startup, the app logs a warning and falls back to in-memory storage instead of refusing to boot. If Redis goes away later, task snapshots fall back to memory and the app keeps running. Leave the AI keys empty to run with the local fallbacks.

`/cached` is a small cache demo: the value is stored for 10 seconds, and the `x-cache` header shows whether it came from the cache.

## Task processing

All processing endpoints return `202 Accepted` immediately with a task ID:

| Endpoint            | Body                    |
| ------------------- | ----------------------- |
| `POST /process/text`  | `{"text":"..."}`      |
| `POST /process/image` | `{"url":"https://..."}` |
| `POST /process/video` | `{"url":"https://..."}` |
| `POST /process/url`   | `{"url":"https://..."}` |

```bash
curl -X POST http://localhost:3000/process/text \
  -H 'content-type: application/json' \
  -d '{"text":"Hello from a background task"}'
# {"taskId":"...","status":"queued"}
```

```bash
curl http://localhost:3000/tasks/<taskId>
# {"id":"...","kind":"text","status":"completed","progress":100,...}
```

Tasks run in-process and always have an in-memory copy for fast access. When Redis was available at startup, snapshots are also written through to Redis with a one-hour TTL, so `GET /tasks/:id` and WebSocket subscriptions can recover a task after a restart or from another instance. If Redis becomes unavailable, task persistence drops back to memory. The actual processing is still in-process, so a task that was mid-flight during a restart is not resumed; a durable queue (for example BullMQ + Redis) would be the next step.

## AI pipeline

The text pipeline is wired as:

```text
ingest → claim gate → summary/claims → RAG lookup → Tier 2 (not wired) → result
```

- **Gate:** Jev when `TYPESAFE_API_KEY` is set, otherwise DeepSeek's own API, otherwise a local heuristic.
- **Summary:** DeepSeek's own API when configured, otherwise an extractive fallback.
- **RAG:** OpenRouter embeddings when configured, otherwise local hashed embeddings. Entries are cached in memory and written through to Redis when available.
- **Transcript:** `src/ai/transcript.ts` returns plain text only, with no timestamps or segments. It can use OpenRouter transcription or DeepSeek ASR (`TRANSCRIPT_PROVIDER=auto|openrouter|deepseek`).
- **Tier 2:** not wired yet. On a RAG miss the task completes as `unverifiable` rather than guessing. A search provider plus the judge/cross-check stage is the remaining piece.
- **Non-text adapters:** image, video, and URL ingestion are not implemented yet; those tasks currently complete as `unverifiable` with an adapter reason. The transcript module is ready for the video adapter.
- **Budget:** each DeepSeek/OpenRouter call adds to `costUsd`; the task stops at `REQUEST_BUDGET_USD`. Jev usage is not priced yet.

Transcripts are normalized to a single `text` string. Provider timestamps, words, and segments are intentionally ignored. DeepSeek ASR accepts WAV/Ogg up to 120 seconds and 8 MiB; OpenRouter transcription is the fallback for longer or other formats.

Result shape:

```ts
interface FactCheckResult {
  checkable: boolean;
  verdict: "true" | "fake" | "misleading" | "unverifiable";
  confidence: number;
  summary: string;
  claims: string[];
  evidence: Evidence[];
  cached: boolean;
  cacheScore?: number;
  costUsd: number;
  modelVersion: string;
  reason?: string;
}
```

Provider modules:

- `src/ai/jev.ts` — typed Jev gate.
- `src/ai/deepseek.ts` — direct DeepSeek chat completions with validated JSON output.
- `src/ai/transcript.ts` — plain-text transcription through OpenRouter or DeepSeek ASR.
- `src/rag.ts` — OpenRouter embeddings, local fallback, Redis-backed cache index.
- `src/pipeline/orchestrator.ts` — stage machine, fallbacks, budget, result assembly.

## WebSocket updates

Elysia has built-in WebSocket support through Bun. Connect to `ws://localhost:3000/ws`.

Client actions:

```json
{"action":"subscribe","taskId":"<uuid>"}
{"action":"unsubscribe","taskId":"<uuid>"}
```

Server events always use a `{ type, data }` envelope:

```ts
type ServerEvent =
  | { type: "connected"; data: { message: string } }
  | { type: "subscribed"; data: { taskId: string; topic: string } }
  | { type: "unsubscribed"; data: { taskId: string; topic: string } }
  | { type: "task.snapshot"; data: { task: Task } }
  | { type: "task.update"; data: { task: Task } }
  | { type: "task.completed"; data: { taskId: string; result: unknown; completedAt: string } }
  | { type: "task.failed"; data: { taskId: string; error: string; failedAt: string } }
  | { type: "error"; data: { code: "invalid_action" | "task_not_found"; message: string } };
```

`task.completed` and `task.failed` are explicit terminal events. A late subscriber gets the current `task.snapshot` plus the terminal event if the task already finished. Intermediate progress arrives as `task.update`.

Minimal client:

```js
const response = await fetch("http://localhost:3000/process/text", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ text: "Hello" }),
});
const { taskId } = await response.json();

const ws = new WebSocket("ws://localhost:3000/ws");
ws.onopen = () => ws.send(JSON.stringify({ action: "subscribe", taskId }));
ws.onmessage = (event) => {
  const message = JSON.parse(event.data);
  console.log(message);

  if (message.type === "task.completed") {
    console.log("Finished:", message.data.result);
    ws.send(JSON.stringify({ action: "unsubscribe", taskId }));
  }
};
```

The protocol types live in `src/tasks/protocol.ts`.

## Cache

The cache is provided by [`@clov-std/kv-store`](https://www.npmjs.com/package/@clov-std/kv-store), which uses Bun's native Redis client. It is exposed to route handlers as `cache`:

```ts
.get("/example", async ({ cache }) => {
  const value = await cache.get<string>("key");
  await cache.set("key", "value", 60); // TTL in seconds
  return { value };
});
```

## Docker

```bash
docker build -t backend .
docker run --rm -p 3000:3000 backend
```

To use Redis, pass the URL at runtime (the `.env` file is not baked into the image):

```bash
docker run --rm -p 3000:3000 \
  -e REDIS_URL=redis://host.docker.internal:6379 \
  backend
```

Set `PORT` too if you want the container to listen somewhere other than `3000`.
